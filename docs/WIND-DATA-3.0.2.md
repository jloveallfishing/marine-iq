# Wind data architecture

3.0.1 discovers NWS forecast grids through coordinate lookups. Several requested coordinates can resolve to the same grid. Grid responses were already cached and shared, but the visual field only used completed three- or four-vertex sample cells. An isolated forecast grid could yield a point label and still leave the underlying map blank.

3.0.2 keeps the bounded viewport scheduler and retains the actual polygon supplied by each NWS grid response. The map reuses the footprint by grid URL and valid forecast hour. It shades supported interpolation between appropriate samples and fills remaining areas only inside a published grid polygon with a fresh reading. Particles follow the fresh directional field. Missing directional readings do not generate flow. In a close zoom wholly contained by a cached fresh grid, the viewport can reuse that grid without issuing another coordinate lookup. No velocities or measurements are synthesized outside supported areas. Tide and current overlays still use independent NOAA station predictions. NWS forecasts may reflect blended models and forecaster edits. MarineCast displays them as forecasts, with its interpolation identified separately from observations.

Live checks reached Richmond (MTR/87,112), Brannan Island (STO/30,49), and the coast near Pacifica (MTR/78,95). Each NWS response supplied a closed five-vertex Polygon and wind series. These checks confirm the endpoint contract at the sampled locations. Forecast completeness still varies by hour and location. [NWS API](https://www.weather.gov/documentation/services-web-api) · [NWS reuse terms](https://www.weather.gov/disclaimer)

## Options for a regional feed

| Source | Fit for MarineCast | Delivery implications |
| --- | --- | --- |
| NOAA NDFD | Typically about 2.5 km for the continental grid. First candidate for a California extract with wind speed, direction and gust validity. Suitable for a multi-day forecast with regional forecaster input. A 2.5 km grid cannot resolve every channel. | Regional GRIB2 ingest would avoid client point discovery. NOAA's XML service supports up to 100 points. CORS and latency for our origin were unverified because this environment's gateway denied the XML test. The browser therefore continues using the existing API. [Metadata](https://www.weather.gov/gis/ndfd_metadata.html) · [XML documentation](https://digital.weather.gov/xml/) |
| NOAA HRRR | About 3 km, frequently updated, useful for short-range coastal wind and model comparison. Verify current availability and NOAA's operational successor timeline before production use. | Decode U/V fields, correctly handle grid-relative bearings and publish cropped, timestamped tiles. Do not use values outside the published model grid or available horizon. [NOAA distribution](https://registry.opendata.aws/noaa-hrrr-pds/) |
| NOAA GFS | Common 0.25° output is suited to broad ocean and longer-range context. It is too coarse to infer local variation in the Bay or Delta. | Publish separately as a named model overlay with explicit run and validity. A backend would subset and compress the grids. [NOAA distribution](https://registry.opendata.aws/noaa-gfs-bdp-pds/) |

The cited NOAA resources describe NOAA data reuse and distribution. Confirm the exact product, attribution and service limits before launch. Access to public forecast data does not include paid compute, storage or service guarantees.

- **Current static beta:** $0 additional operating cost. Uses the existing NWS API and the published cell footprint.
- **Scheduled regional extract:** An existing machine or eligible public GitHub Actions minutes could prototype a bounded extract at $0 incremental hosting cost. Measure cadence, runtime, repository growth and operational reliability before adopting it. This is a prototype path. GitHub Pages restrictions still apply to commercial hosting.
- **Managed distribution:** As an illustrative option, Cloudflare Workers Paid starts at **$5/month**. R2 Standard storage at the listed $0.015/GB-month would be **$0.15/month** for 10 GB-month before eligible allowances. Operations and the GRIB decode job are separate. Benchmark CPU time and request volume before estimating production totals. No services were provisioned.
